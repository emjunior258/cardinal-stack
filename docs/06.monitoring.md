# Monitoring Metrics

This document describes the operational metrics exposed by cardinal-stack. Metrics are intended to give operational teams the right level of visibility into the health and behaviour of the platform, including the USSD transactions users are attempting to perform.

Where noted, metrics are broken down by **MNO** (via a `network` label/dimension) to allow per-operator analysis which is  essential for capacity management, cost control, and incident isolation.

> **Note on tracing:** Low-level internal processing details (e.g. engine pipeline stages) are better served by distributed tracing and are intentionally excluded from this metrics catalogue.

---

## Dimensions / Labels

The following common dimensions are used to slice metrics throughout this document:

| Dimension        | Description |
|------------------|-------------|
| `network`        | Mobile Network Operator identifier (e.g. `mno-a`, `mno-b`) |
| `space`          | Tenant / space identifier |
| `application`    | Application identifier |
| `entry_point`    | Entry point identifier |
| `short_code`     | USSD short code (e.g. `*123#`) |
| `session_type`   | `dial` or `push` |
| `activity`       | Activity identifier (e.g. `main-menu`, `transfer`, `login`) |
| `backend`        | Backend service identifier |
| `status`         | Outcome status (varies by metric group) |

---

## 1. Session Metrics

Provide a real-time and historical view of USSD session volume and outcomes. These are the primary health indicators for the platform.

> **Breakdown by MNO**: required on all metrics in this group.

| Metric | Type | Description | Dimensions |
|--------|------|-------------|------------|
| `sessions_started_total` | Counter | Total number of sessions initiated | `network`, `space`, `application`, `entry_point`, `short_code`, `session_type` |
| `sessions_active` | Gauge | Number of sessions currently active | `network`, `space`, `application`, `entry_point`, `session_type` |
| `sessions_ended_total` | Counter | Total sessions ended, by final status | `network`, `space`, `application`, `entry_point`, `session_type`, `status` (`completed`, `cancelled`, `crashed`, `expired`, `terminated`) |
| `session_duration_seconds` | Histogram | Duration of completed sessions from start to end | `network`, `space`, `application`, `entry_point`, `session_type` |
| `sessions_excluded_total` | Counter | Sessions rejected due to short list exclusion | `network`, `space`, `application`, `entry_point` |
| `sessions_suspended_total` | Counter | Sessions blocked due to active entry point suspension | `network`, `space`, `application`, `entry_point` |
| `sessions_no_entry_point_total` | Counter | Requests received with no matching entry point | `network`, `short_code` |

**Key derived indicators:**
- Session crash rate = `sessions_ended_total{status="crashed"}` / `sessions_started_total`
- Session completion rate = `sessions_ended_total{status="completed"}` / `sessions_started_total`
- Session abandonment rate = `sessions_ended_total{status="cancelled"}` / `sessions_started_total`

## 2. Activity Metrics

Provide visibility into the individual screens/activities that users navigate through. This is the primary lens for understanding **what transactions users are attempting** — e.g. how many users reach the `transfer` activity, how many complete it, and where drop-offs occur.

| Metric | Type | Description | Dimensions |
|--------|------|-------------|------------|
| `activity_visits_total` | Counter | Total number of times an activity was visited (screen presented to user) | `network`, `space`, `application`, `entry_point`, `activity` |
| `activity_completions_total` | Counter | Total times a user successfully moved forward from an activity (provided valid input) | `network`, `space`, `application`, `entry_point`, `activity` |
| `activity_dropoffs_total` | Counter | Times a session ended (cancelled / expired / crashed) while the user was on a given activity | `network`, `space`, `application`, `entry_point`, `activity`, `status` |
| `activity_input_processing_duration_seconds` | Histogram | Time taken to process and validate the user's input for an activity and resolve the next navigation step | `network`, `space`, `application`, `entry_point`, `activity` |
| `activity_content_retrieval_duration_seconds` | Histogram | Time taken to retrieve and render the content to be displayed for an activity (e.g. fetching screen content from the backend) | `network`, `space`, `application`, `entry_point`, `activity` |
| `activity_redirects_total` | Counter | Redirects triggered from an activity | `network`, `space`, `application`, `entry_point`, `activity`, `redirect_type` (`internal`, `external`) |

**Key derived indicators:**
- Activity funnel conversion = `activity_completions_total{activity="X"}` / `activity_visits_total{activity="X"}`
- Drop-off rate per activity = `activity_dropoffs_total{activity="X"}` / `activity_visits_total{activity="X"}`
- Activity input processing p99 latency from histogram `activity_input_processing_duration_seconds`
- Activity content retrieval p99 latency from histogram `activity_content_retrieval_duration_seconds`

## 3. Backend Metrics

Track the health and performance of upstream USSD application backends. Degradation here directly impacts user experience.

| Metric | Type | Description | Dimensions |
|--------|------|-------------|------------|
| `backend_requests_total` | Counter | Total HTTP requests sent to a backend | `space`, `application`, `backend`, `request_type` (`execute`, `app_map`) |
| `backend_request_duration_seconds` | Histogram | Latency of backend HTTP requests | `space`, `application`, `backend`, `request_type` |
| `backend_errors_total` | Counter | Backend requests that resulted in an error | `space`, `application`, `backend`, `request_type`, `error_type` (`timeout`, `connection_refused`, `http_5xx`, `invalid_response`) |
| `backend_http_responses_total` | Counter | Backend HTTP responses by status code | `space`, `application`, `backend`, `request_type`, `status_code` |
| `backend_app_map_fetch_total` | Counter | Total application map fetch attempts | `space`, `application`, `backend`, `status` (`success`, `failure`) |
| `backend_app_map_age_seconds` | Gauge | Age of the currently cached application map | `space`, `application`, `backend` |
| `backend_redirects_received_total` | Counter | 307 redirects received from backends | `space`, `application`, `backend`, `redirect_type` (`internal`, `external`) |

**Key derived indicators:**
- Backend error rate = `backend_errors_total` / `backend_requests_total`
- Backend p99 latency from histogram `backend_request_duration_seconds`

---

## 4. Edge Server Metrics

Track inbound traffic arriving from MNO gateways and outbound USSD Push requests.

> **Breakdown by MNO**: required on all metrics in this group.

| Metric | Type | Description | Dimensions |
|--------|------|-------------|------------|
| `edge_requests_received_total` | Counter | Total USSD requests received from MNO gateways | `network`, `short_code` |
| `edge_request_duration_seconds` | Histogram | End-to-end request processing latency at the edge | `network` |
| `edge_request_errors_total` | Counter | Requests that could not be processed (invalid format, auth failure, etc.) | `network`, `error_type` |
| `edge_push_sent_total` | Counter | USSD Push requests dispatched to MNO gateways | `network`, `space`, `application`, `entry_point` |
| `edge_push_errors_total` | Counter | USSD Push requests that failed at the MNO gateway level | `network`, `space`, `application`, `entry_point`, `error_type` |
| `edge_push_duration_seconds` | Histogram | Latency of USSD Push dispatch to MNO | `network` |

---

## 5. USSD Push Metrics

Track push session initiation from the application-side.

| Metric | Type | Description | Dimensions |
|--------|------|-------------|------------|
| `push_initiated_total` | Counter | Total USSD push sessions requested by applications | `network`, `space`, `application`, `entry_point` |
| `push_accepted_total` | Counter | Push requests accepted and forwarded to MNO | `network`, `space`, `application`, `entry_point` |
| `push_rejected_total` | Counter | Push requests rejected (auth failure, network not entitled, rate limit, etc.) | `network`, `space`, `application`, `entry_point`, `reason` |
| `push_delivery_duration_seconds` | Histogram | Time from push request to MNO acknowledgement | `network` |

## Suggested Alerts

| Alert | Condition | Severity |
|-------|-----------|----------|
| High session crash rate | `crash_rate > 5%` over 5 min per MNO or application | Critical |
| Backend error rate spike | `backend_errors_total rate > 10%` over 2 min | Critical |
| Backend latency p99 high | p99 `backend_request_duration_seconds > 3s` over 5 min | Warning |
| Activity content retrieval latency high | p99 `activity_content_retrieval_duration_seconds > 2s` over 5 min | Warning |
| Activity input processing latency high | p99 `activity_input_processing_duration_seconds > 1s` over 5 min | Warning |
| No sessions received from MNO | `edge_requests_received_total{network="X"} rate == 0` for 5 min (during expected traffic hours) | Warning |
| Application map unavailable | `backend_app_map_fetch_total{status="failure"} rate > 0` over 2 min | Critical |
| Activity drop-off anomaly | `activity_dropoffs_total{activity="X"}` rate increases > 50% compared to baseline | Warning |
